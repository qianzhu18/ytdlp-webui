## 正文

1800+。

这是幕库 Muku 现在接入的 yt-dlp 视频解析器生态规模。

我之前介绍幕库 Muku 时，总说它支持 B站、YouTube 和抖音。

这句话没错，但确实把它说小了。

因为幕库底层接的是 yt-dlp。按现在的解析器范围，1800+ 个视频网站的完整链接，都可以先尝试进入同一条处理链路。

更准确地说：B站、YouTube、抖音是我重点适配的主链路；其他 yt-dlp 能解析的站点，只要能拿到字幕或音频，幕库就能继续往下整理。

一条视频，最后会变成：

• 原始逐字稿
• 清洗后的可读文本
• 结构化解析稿
• 可放进 Obsidian / RAG 的知识库 Markdown

所以我真正想做的，不是再包一个“视频下载器”，而是补上收藏之后最容易断掉的那段路：

视频链接 → 字幕 / 音频 → 逐字稿 → 解析稿 → 自己的知识库。

现在它已经支持：

• 接入 yt-dlp 1800+ 站点解析入口
• 字幕优先，拿不到字幕再回退音频转写
• 批量 URL、并发、断点续跑
• Web UI、CLI、Docker、AI-agent Skill 四种入口
• 文件、配置和知识资产本地保存

这次公开发布前，我也拿真实链接重新跑了一轮：YouTube 和 TED 可以直接提取字幕，B站和抖音可以取音频，混合 URL 批量处理与断点续跑也能工作。不同网站仍然会受登录态、网络和平台改版影响，所以我不会把“1800+”包装成逐站保成功。

第一次使用也不用先研究一堆配置：

macOS / Linux：

```bash
curl -fsSL https://raw.githubusercontent.com/qianzhu18/Muku/main/scripts/install-muku | bash
muku quickstart
```

Windows PowerShell 也有对应安装脚本。

当然，1800+ 不是“我手工测完了 1800+ 个站”，也不是每条链接都保证成功。这个数字来自 yt-dlp 的解析器生态；站点改版、Cookies、网络、地区和 DRM 都会影响结果。最可靠的方法，永远是拿自己的真实链接跑一次。

它也是本地优先，不是纯离线。文件、配置和最终产物默认留在本地，但转写和 AI 整理会调用你自己配置的 AI 服务，API Key 和 Cookies 需要自己保管。

现在的 Muku 还是 v0.x，但下载、字幕、转写、清洗、解析和知识库已经拆成了一条可以继续扩展的链路。后面还能继续接更多平台、模型、模板和更轻的入口。

不是先等它“全部做完”，而是先让一条视频真正进入自己的系统。
